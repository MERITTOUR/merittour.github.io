1. 시스템 개요

1.1 목적

골프투어 회원권 보유 고객이 회원 우선예약 기간에 원하는 골프장·일정·인원을 직접 예약하는 웹 서비스. 기존에는 전화·카카오톡으로 접수하던 예약을 회원이 직접 진행하고, 사내 예약 시스템(엠클릭)과 상태를 연동한다.

1.2 대상 사용자

구분설명특징
정회원회원권 보유 본인전 차수 우선예약 참여
지정회원회원권에 지정된 동반 회원정회원과 동일 회원권 기준 적용
특별회원특별 회원권3차 우선예약만 참여 (§5)
사용자 특성 — 이용 고객의 상당수가 50~70대이며 모바일 예약 비중이 높다. 글자 크기·터치 영역·단계 수를 시니어 기준으로 설계할 것. (§9.3)

1.3 설계 원칙

  1. 선택은 즉시 반영 — 「적용」 버튼 없이 고르면 바로 적용되고 다음 항목으로 자동 이동.
  2. 스크롤 최소화 — 큰 사진·장식 최소화, 첫 화면에서 검색 시작 가능.
  3. 4가지 질문으로 예약 — 어디서 / 어디로 / 얼마나 / 몇 명.
  4. 회원 기준 자동 제한 — 인원 상한·예약 가능 횟수를 회원권 기준으로 화면에서 강제.

5. 우선예약 차수 운영 핵심

5.1 차수 개방 · 횟수 누적

정해진 시각에 차수가 열리고, 열릴 때마다 예약 가능 횟수가 누적된다. 회원권 종류와 무관하게 동일한 횟수를 배정한다.

차수개방 시각 (예시)추가 횟수누적 가능참여 대상
1차10/12 (월) 10:00+1회1회정회원·지정회원
2차10/13 (화) 10:00+2회3회정회원·지정회원
3차10/14 (수) 10:00+2회5회정회원·지정회원 + 특별회원
자유예약10/15 (목) 10:00—잔여 객실전 회원
  • FR-5.1 1차 개방(10/12 10:00) 후 10/13 09:59:59까지는 1회, 10/13 10:00에 3회, 10/14 10:00에 5회가 된다(초 단위 정확도 필요).
  • FR-5.2 특별회원은 3차만 참여 → 3차 개방 시 2회. 1·2차는 화면에 「해당 없음」으로 표시.
  • FR-5.3 개방 시각·횟수·자유예약 개방일은 운영자가 관리 화면에서 변경할 수 있어야 한다(연도마다 달라짐).
  • FR-5.4 개방 전에는 「1차 우선예약 10/12(월) 10:00 오픈 · +1회 추가」처럼 오픈 일정과 추가 횟수를 안내한다.
  • FR-5.5 예약 1건 확정 시 열린 차수 중 잔여가 있는 차수에서 1회 차감한다.

5.2 남은 횟수 표시 위치

위치표시 내용
랜딩 상단예약 가능 3회 · 1차 잔여 1회 · 2차 잔여 2회 · 3차 10/14(수) 10:00 오픈 + 다음 차수 오픈 안내
로그인 완료회원권·예약 가능 인원 + 남은 예약 가능 횟수
마이페이지차수별 사용/배정 횟수, 진행바, 미개방·해당없음 상태
예약 확인「확정 시 우선예약 1회가 사용됩니다」 + 예약 후 남는 횟수
예약 완료·알림사용한 차수 + 남은 횟수
FR-5.6 예약 가능 횟수가 0이거나 차수가 열리지 않았으면 예약 진행을 차단하고, 다음 차수 오픈 일정과 대기 신청 가능 안내를 제시한다.

6. 예약 요구사항

6.1 인원 규칙

  • FR-6.1 최소 2명부터 예약 가능 (1명 불가 — 감소 버튼 비활성).
  • FR-6.2 최대 = 회원권 예약 가능 인원. 상한 도달 시 증가 버튼 비활성 + 「최대 N명(회원권 기준)」 안내.
  • FR-6.3 객실 수는 2인 1실 기준으로 자동 환산해 표시(예: 4명 → 2실). 4인실(패밀리룸)이 있는 숙소는 룸타입에 따라 환산이 달라지므로 숙소별 정원 데이터를 사용한다.
  • FR-6.4 홀수 인원은 화면에서 받되, 싱글 차지 등 추가 요금은 사후 수기 정리(자동 계산하지 않음).

6.2 예약 가능 달력

표시조건동작
예약 가능출발 요일 일치 + 시즌 시작 이후 + 잔여 있음날짜 아래 잔여 실수 표시, 선택 가능
마감잔여 0클릭 시 예약 대기 신청으로 전환(§7)
비활성출발 요일 불일치 또는 시즌 시작 전선택 불가
  • FR-6.5 숙소별 출발 요일·박수 패턴만 선택 가능(예: 야마나미 3박=목, 4박=일, 7박=수).
  • FR-6.6 잔여는 보유 − 사용(사내 블록 관리와 동일 기준). 연박은 체류 전 기간의 최소 잔여로 판정해야 한다(하루라도 부족하면 예약 불가).
  • FR-6.7 월 이동(◀▶)은 시즌 범위 내에서만 허용.

6.3 금액 표시

  • FR-6.8 1인당 금액과 총액(인원×1인)을 함께 표시.
  • FR-6.9 연부킹(단체 발권) 상품은 항공 발권 전이라 「항공요금은 발권 확정 후 안내」로 표기하고, 숙박·송영 기준 금액을 안내한다. 항공 포함 확정가 상품(무츠키·스가다이라)은 「왕복 항공 포함」으로 표기.
  • FR-6.10 단가·환율은 사내 마스터 값을 사용한다(숙소별 현지 단가, 송영비, 월별 환율).

6.4 예약 확인 · 확정 · 완료

단계필수 표시 항목
S-04 예약 확인숙소명, 기간(N박 M일·출발 요일), 출발일, 인원, 객실 수, 예약자(이름·회원권·회원구분), 1인/총 금액, 확정 시 1회 사용 안내, 예약 후 남는 횟수, 변경·취소 문의 안내
S-05 예약 완료예약번호, 숙소·출발일·인원, 사용한 차수, 남은 횟수, 예약금 안내 경로(카카오톡 채널·문자)
  • FR-6.11 확정 시 예약번호 발급 · 차수 1회 차감 · 예약 내역 등록 · 알림 표시가 하나의 트랜잭션으로 처리되어야 한다.
  • FR-6.12 동시 예약으로 잔여가 없어지는 경쟁 상황에서 초과 예약(오버부킹)이 발생하지 않아야 한다(확정 시점 재검증 필수).
  • FR-6.13 확정 후 상태는 사내 예약 시스템의 구분값과 연동한다(§9.2).

7. 예약 대기 신규

마감된 일정도 회원이 대기를 걸 수 있게 한다. 사내 예약 구분값의 「대기」를 활용한다.

  • FR-7.1 달력에서 마감 날짜도 클릭 가능. 선택 시 CTA가 「예약 대기 신청」으로 전환된다.
  • FR-7.2 신청 화면에 숙소·출발일·기간·인원과 안내(대기 순서대로 연락, 대기 중 요금 미청구, 회원 정보의 연락처로 안내)를 표시한다.
  • FR-7.3 접수 시 예약 상태 「대기」로 등록하고, 대기 순번을 관리한다.
  • FR-7.4 취소분 발생 시 대기 순서대로 담당자가 연락·전환할 수 있어야 한다(자동 확정 여부는 운영 정책에 따라 결정).
  • FR-7.5 대기 신청은 예약 가능 횟수를 차감하지 않는다(확정 전환 시 차감).

8.1 마이페이지 (S-07)

  • 회원권 정보: 예약 가능 인원, 회원대우(지정인) 수
  • 우선예약 사용 현황: 차수별 사용/배정 + 잔여, 미개방은 오픈 예정일, 특별회원 1·2차는 「해당 없음」
  • 예약 내역 요약(확정·대기·견적 건수) → 예약확인 화면 이동
  • 계정: 비밀번호 변경, 정보 수정 문의 안내, 로그아웃

8.2 예약확인 / 결제 (S-08)

  • FR-8.1 본인 예약만 조회. 항목: 숙소, 기간·출발일, 인원, 예약번호, 상태 배지, 미결제 잔액.
  • FR-8.2 상태는 사내 구분값과 동일: 견적 확정 정산 대기 취소
  • FR-8.3 결제·일정 변경·취소는 담당자 처리(화면에는 문의 안내). 온라인 결제 연동은 2단계 과제(§10.2).

8.3 고객센터 (S-10)

8.4 알림
